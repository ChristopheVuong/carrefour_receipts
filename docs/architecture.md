# Architecture

The project is a small but complete analytics stack over personal Carrefour receipts.
Data flows left to right; each stage is independently runnable.

```
 Carrefour portal
       │  curl + browser-exported cookies            (api-extraction.md)
       ▼
 JSON receipts + loyalty + Drive orders  ──▶  data/  (git-ignored, PII)
       │  dlt  (carrefour_receipts_api.elt.load)
       ▼
 DuckDB  raw schema            ──▶  carrefour.duckdb
       │  dbt  (transform/)
       ▼
 staging → intermediate → marts → marts/analytics       (dbt docs)
       │  duckdb
       ▼
 Streamlit dashboard           ──▶  http://localhost:8501   (dashboard.md)
```

## Stages

| Stage | Code | Output |
| --- | --- | --- |
| **Extract** | [user_api_extractor.py](../src/carrefour_receipts_api/user_api_extractor.py) | JSON under `data/` |
| **Load (EL)** | [elt/load.py](../src/carrefour_receipts_api/elt/load.py) (dlt) | `raw.*` tables in DuckDB |
| **Transform (T)** | [transform/](../transform/) (dbt) | star schema + analytics marts |
| **Process (Python in dbt)** | [matching.py](../src/carrefour_receipts_api/matching.py), [categorization.py](../src/carrefour_receipts_api/categorization.py), [embeddings.py](../src/carrefour_receipts_api/embeddings.py) | imported by the dbt Python models |
| **Serve** | [dashboard/dashboard.py](../src/carrefour_receipts_api/dashboard/dashboard.py) (Streamlit) | interactive dashboard + NL [assistant](assistant.md) (text-to-SQL) |

## Design choices

- **Separation of two doc systems.** The data-mart reference (models, columns, lineage,
  tests) is generated by dbt (`make docs-dbt`) and is independent of this codebase
  documentation. These `docs/` pages describe the Python code and how to operate the
  stack; they do not duplicate the dbt model catalog.
- **ELT, not ETL.** dlt loads raw data unchanged (auto-unnesting nested JSON into child
  tables); all transformation happens in dbt where it is tested.
- **Env-driven config.** Paths, the DuckDB location and matching thresholds live in
  [config.py](../src/carrefour_receipts_api/config.py) / `.env`, never hard-coded.
  dbt Python models read these from the environment (dbt vars aren't visible to them).
- **CI-safe by construction.** The fidélité match and product categorization use
  rapidfuzz (deterministic), so the whole dbt build runs in CI without downloading any
  model. The fastembed (ONNX) path is optional and off by default.
- **No MongoDB.** The legacy MongoDB aggregation pipelines were fully removed; the modern
  stack replaces them.
- **Deployment boundary.** Auth + extraction stay host-side CLI (they need a real browser for
  Cloudflare); the EL+dbt step (`make build`) can run locally or as a re-runnable container
  job. The merge-based load makes it idempotent — see [deployment.md](deployment.md).

## Repository layout

```
src/carrefour_receipts_api/   Python package (extraction, ELT, processing, dashboard)
transform/                    dbt project (staging → intermediate → marts → analytics)
tests/                        unit + integration tests, committed fixtures
docs/                         this codebase documentation
data/                         git-ignored raw data (PII) — never committed
```
